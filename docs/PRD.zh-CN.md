# geo_regions 产品需求文档

版本：1.0 delivery baseline · 日期：2026-11-13 · 状态：可执行设计基线，生产 SDK 尚待实施

英文对应：[PRD.en.md](PRD.en.md)。实施计划：[PLAN.zh-CN.md](PLAN.zh-CN.md)。协议：[PROTOCOL.md](PROTOCOL.md)。本文件和英文版具有相同需求编号。

## 1. 已确认的产品决策

`geo_regions` 名称已确定，不再设置名称评审阻塞点。目标是一个独立、可贡献、可商用的 Flutter 地区数据与选择组件库，IMBoy 为首个真实接入者。主包的运行时依赖仅 Flutter/Dart SDK；网络、持久存储、哈希实现和宿主业务通过接口接入。

项目维护完整的地区资源体系：结构、国家清单、地区名称语言包、来源、版本、质量状态、生成及校验工具。开发者获取当前已发布的全部数据，并配置哪些国家结构、哪些国家×语言组合随 App 离线发布，剩余资源运行时按需加载。全量数据可获取与全量数据随 App 打包是两个独立约束。

最终覆盖目标是全球国家和地区。本交付包先提供十国种子数据，不能把这十国、上游已收录的层级或语言回退计为全球覆盖完成。数据扩展沿用同一流程，无须改核心 SDK。

根目录 `LICENSE` 沿用仓库已有 BSD-3-Clause；第三方数据保留原许可与署名。产品不要求账号、密钥、IMBoy 服务、遥测或固定 CDN。开源许可不意味着放弃署名等条件。[S01][S02][S03]

## 4. 使用者与边界

SDK 使用者可以只用数据 API，也可用默认选择组件；可完全离线、使用公共数据镜像、企业私有源或自己维护的兼容数据。宿主负责用户资料保存、登录态、业务校验、主题、界面国际化、路由及后端兼容。

默认 UI 提供 `GeoPickerLabels`、主题和节点构建器扩展；不能依赖 IMBoy 的 Riverpod、slang、`UserRepoLocal` 或 `MorePage`。地区名称与 UI 的“搜索/返回/完成/重试”文案独立。

非目标：地图、GPS、逆地理编码、邮政地址验证、电话区号输入、边界多边形、自动拼音、全球所有行政层级及全语种人工译名一次性完成。上述内容不混入本次 SDK 的完成标准。

## 5. 功能需求及验收契约

| ID | 需求 | 必须通过的验收 |
|---|---|---|
| GR-01 | 一个国家一份结构，任意有限层级，稳定 ID | 同名节点不冲突；完整 root→selected-node 路径可还原；支持国家单独选择 |
| GR-02 | 国家目录、目录名称、地区结构、地区译名分离 | 新增语言不改任一 `regions/*.json` 的字节或 revision |
| GR-03 | 国家×语言独立离线配置 | CN 结构 + CN 中文、英文；JP 结构 + JP 日文的构建样本实际只含这些文件 |
| GR-04 | 在线按需获取 | 打开 JP 不请求 US/DE 等结构；切换语言不重新下载同一版本结构 |
| GR-05 | 缓存、去重与并发一致性 | 同资源并发一次加载；切换国家/语言的旧响应不覆盖新状态；dispose 后无更新 |
| GR-06 | 完整性与版本 | 先核对长度、SHA-256，再解析；失败不替换有效缓存；不混合不兼容结构/译名 |
| GR-07 | 质量可见的名称回退 | 返回 requested/resolved locale、来源质量及是否 fallback；draft 不计已审核 |
| GR-08 | 查询与搜索 | 按 ID、父子关系、名称、别名查询；结果携带完整路径，重名可辨别 |
| GR-09 | 可用且易接入的 UI | 第一节点有 Demo；手机/桌面、键盘、RTL、暗色、大字体及错误恢复可验收 |
| GR-10 | 业务选择策略可配置 | country-only、允许中间节点、指定业务层级、受支持的叶节点可分别测试 |
| GR-11 | 数据治理 | 每资源可追溯固定源 revision、SHA-256、许可、转换、日期和覆盖；可离线重建 |
| GR-12 | 依赖边界 | 主包 dependencies 无第三方 runtime 包；HTTP/store/hash 适配独立，不偷偷直接 import dart:io 到 Web 入口 |
| GR-13 | 跨平台与包体 | Web、Android、iOS、桌面策略明确；实际产物清单证明未选数据未被打包 |
| GR-14 | IMBoy 行为兼容 | 服务端成功后提交缓存并返回 MorePage；失败保留选择，重复点击不重复提交 |
| GR-15 | 可重复发布 | PR 自动门禁，数据发布可重建；代码和数据版本独立；推送后有真实 CI 证据 |
| GR-16 | 无固定服务依赖 | 换镜像与完全离线示例都能使用；无 API key、登录或遥测前置 |

## 6. 数据与协议原则

规范为 Geo Regions Data Protocol 1.0，是建立在现有标准上的项目数据契约，不是新互联网标准。采用 ISO 国家代码、BCP 47、RFC 8259 UTF-8 JSON、JSON Schema 2020-12、标准 URI/HTTPS 与 HTTP 缓存语义。[S04]–[S10]

地区身份是 `(datasetId, countryCode, nodeId)`；选择值携带 `pathIds` 和 `dataRevision`。`pathIds` 第一项必须为 `cc:XX` 国家根；只选国家也有一项。显示名或以空格拼接的路径不是身份。行政编码变更、合并、撤销通过迁移记录处理，不能在新版本默默复用旧 ID 给另一实体。

`childrenStatus` 描述声明的数据范围是否完整，不能把加载失败或未知范围转换为“没有下级”。范围未知时 `mustSelectLeaf` 不得错误放行；应显示数据支持范围，并由宿主选择允许中间层级或阻止提交。

Manifest 包含资源相对路径、kind、revision、SHA-256、字节数及兼容关系。内容哈希验证的是内容完整性，不证明名称正确，也不能在 Manifest 一并被攻击者替换时提供独立身份认证。远程模式须有可信 Manifest 获取通道；签名扩展可以后续实现，但不能声称现有 SHA-256 已完成签名验证。

## 7. 开发全量与生产子集

1. `data/` 作为包内普通文件随已发布包下载，不在主包 `flutter.assets` 中声明全量目录。
2. 当前 Python 开发工具可从仓库生成离线子集；Phase 1 实现 `dart run geo_regions:assets` 的宿主友好入口，从已解析 package 根定位数据，不能硬编码 pub cache 路径。
3. 宿主显式声明生成文件。必须注意 Flutter 目录声明不自动递归覆盖所有子目录，生成工具应输出精确 asset 条目或稳定的平铺索引，不靠一个目录行猜测。[S06]
4. `pub get` 不被当作任意生成脚本的自动执行钩子。准备资源命令必须接在本地构建与 CI 构建之前，缺失或陈旧配置直接失败。
5. 随包 `manifest.json` 只列实际随包资源；`registry.json` 可以列全体远程资源描述，描述不等于把远程文件内容打包。
6. 发布前运行 `pub publish --dry-run` 并测量 gzip/uncompressed 大小。若未来全球资源超服务限额，必须明确解决打包方案并重新确认产品承诺，不能悄悄把“pub get 获得全部已发布数据”改成手工找数据。[S02]

## 8. 加载与缓存策略

V1 默认选择一个不可变发布集合。匹配所选 revision 的 bundled/cache 资源均可使用；缺失才调用 loader。资源以 datasetId、kind、country、locale、revision、hash 分隔缓存。与当前 Manifest 不匹配的旧缓存不能冒充命中。

更新应先下载并验证完整兼容资源集合，再原子切换活动 Manifest。下载中断不改变当前选择或缓存引用。离线时可使用前一次完整兼容发布集合，并明确 stale 状态；禁止把不同发布集合的结构和译名拼起来。持久层原子写入由注入的 store 契约负责。

宿主选择缓存配额、LRU、过期、清理策略。数据缓存可共享公开资源；用户选择和账号资料不能跨账号共享。请求可尽力取消；即使底层无法取消，generation token 也必须防止过时响应提交。

严格远程模式未注入可靠 SHA-256 verifier 时应报配置错误。主库不为了“零依赖”自行编写密码学算法。离线资源的发布期校验与远程运行期校验要分别描述，不能相互替代。

## 9. 多语言与质量策略

候选匹配顺序为：规范化请求及显式别名 → RFC 4647 风格匹配可用 locale → 宿主默认 locale → 节点来源默认名 → stable ID。具体 fallback 链可配置，且返回实际命中信息。UI 可以对缺失与暂定译名做轻量提示，不暴露内部堆栈。

CLDR 原始 draft 状态逐 ID 保留；`approved-in-source` 只代表上游状态，不代表项目人工复核。生产默认只接受明确的 approved-in-source、contributed、cldr-json-qualified、source-native 质量状态；provisional、unconfirmed、candidate 及未知状态默认拒绝。结构默认名的 nameQuality/nameLocale 同样参与判断，不能通过回退 node.name 绕过过滤；种子预览可显式允许展示暂定名称并标注。`source-native` 名称不等于其他九种语言翻译。源的繁体中文缺口要以任务补齐，未经验证的简繁转换不能伪称来源译名。

新语言只新增语言资源、目录名称及登记项，结构文件 hash 必须保持不变；新国家增加独立结构与语言包，现有国家不应无关变更。新增流程需生成覆盖、来源、license 与差异报告。

## 10. UI/UX 验收

第一节点以 [DEMO_UX.md](DEMO_UX.md) 为视觉与交互标准。核心是快速理解“正在选择哪个国家、到了哪一级、当前能否完成、数据从何处可用”，不是堆砌组件。

必须有：窄屏单列与宽屏双栏、完整面包屑、明确的当前选择、可见搜索清除、加载占位、无结果、无网络且无缓存、下载失败重试、缓存/离线状态；保存时防重复提交。颜色和文字共同表达状态，触控目标目标值不小于 44 logical px，字体放大 200% 不遮挡关键操作。阿语布局按 Directionality 镜像，ID/代码仍保持可读顺序。键盘可完成整个选择；读屏可获得名称、选中状态、层级和加载状态。

截图是设计验收证据之一，不能替代真实交互测试；HTML 参考不是 Flutter 编译、原生渲染或设备测试的证据。

## 11. 性能与可测试性

性能门槛以发布构建、记录的硬件与数据规模衡量：暖缓存名称查找/父子查询避免重复 JSON 解码；单国首次解析和搜索分别输出 p50/p95 与节点数；基准设备上搜索首批结果目标 p95 <150ms，超标需说明并改进。该目标是验收预算，不是本次测得结果。

模拟 loader/store/clock/verifier 使失败、乱序、并发、旧缓存、损坏和 revision 不匹配可确定性复现。Widget fixture 验证 UI；独立 repository 测试必须覆盖真实解析与缓存调用，禁止用覆盖初始化的 Widget 假对象宣称数据链路已通过。

## 12. 两阶段完成定义

**Phase 1：独立库。** Demo 首先可见；协议、数据与许可明确；实际 SDK、可选 UI、Dart 资产 CLI、真实离线/远程示例、质量策略、测试、包体检查和 CI 门禁完成。十国支持范围明确，十语能加载和回退；未复核或未收录部分列入可执行队列，不得写“全球完整”。公开发布是独立动作，默认准备草稿，不擅自上传 pub.dev。

**Phase 2：IMBoy。** 在现有代码和工作树上接入或隔离到固定任务工作树；旧字符串资料兼容，稳定 ID 保存与后端协议经过真实检查；缓存、导航、十语、Flutter Web 与设备回归有证据。后端与管理端只有实际 API/显示需求才修改，不设想不存在的接口。

任一阶段存在关键 SKIP/BLOCKED，不得标完成。无法提供设备、账号或发布配置时，可以继续独立工作并输出精确阻塞；阻塞项不计为 PASS。
